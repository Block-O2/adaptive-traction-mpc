## Remaining limitations and decision

The 5.059 N first-edge result proves infeasibility for the *implemented* zero-slope α=0 first step. The saved endpoint event does **not** prove that every nonzero α is infeasible, nor isolate how much of the reanchor came from changed geometry, reference/pose, allocation, sensor/estimated state evolution or their interaction. DEV-B's ~97% dynamics projection applies to its own matched activation and must not be extrapolated to this case. The analytic revision-4 alpha interval is exact for an affine preview segment but CR12 torque clipping can be non-affine; the selected candidate and actual command are rechecked before actuation, so a mismatch fails closed rather than establishing a global maximum feasible alpha. Direct-small-change and external BRAKE paths are outside that in-flight TRACK envelope guarantee.

The DEV-B decision expressly required explicit refusal when the old/new command cannot be connected under retained constraints. The v3 fail-closed behavior respects that boundary, but it does **not** meet the requested full Human/cuff/CR12 finite-takeover objective across the development cases. A coordinated downstream wrench/geometry/reference handoff or another justified output bridge would be a separately scoped design; it should not be silently introduced, and neither the consumed v2 replay nor four local matched PASS results justify promoting the current controller. The single next step recommended in `DEV_C_REPORT.md`—a matched-state deployable-input diagnosis of the recovery-start action-to-wrench reanchor—is proportionate to this evidence.
