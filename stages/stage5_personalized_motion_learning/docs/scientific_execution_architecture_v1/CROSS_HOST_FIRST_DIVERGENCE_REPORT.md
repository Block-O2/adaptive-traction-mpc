## Low-ROM event chain and root cause

At the recorded **initial boundary, 0 s**, Mac CR12 q is approximately `[-2.120286, -1.074396, 2.234961, -0.555807, -1.713680, 1.585054]` rad; WSL q is `[1.021307, 1.074396, -2.234961, 2.585786, -1.713680, 1.585054]` rad. The first-joint difference is pi radians. The two configurations place the attachment at almost the same pose: 3.28e-14 m translation and 1.36e-14 rad orientation apart in a read-only WSL forward-kinematics check. In that same WSL calculation, their minimum Jacobian singular values are 0.2955150935225191 and 0.29551509352251587, only about 3.2e-15 apart.

`cr12_plant.py::solve_cr12_stage5_ik` uses fixed multi-start seeds and selects the exact IK candidate with the largest minimum Jacobian singular value. `full3d_adaptive_integration_v1/runtime.py::_initialize_loaded_runtime` invokes this during reset and then keeps continuity from the selected joint branch. The nearly tied score and identical attachment pose support a cross-host tie-order flip in **initial IK branch selection**. The source code and raw evidence establish the branch change; the individual Mac solver candidate scores were not saved, so the precise floating-point operation that reversed candidate order remains an inference. The result is category **B: discrete threshold/branch sensitivity**, with a category-C symptom (early material scientific mismatch). It is not an ordinary epsilon drift that gradually grew from the same initial joint state. Scientific package versions match; a dependency-version mismatch is not supported by the evidence.

The initial branch changes the first native joint-2 command from +142.425570 Nm on Mac to -142.361704 Nm on WSL. At the first force/moment trace node after reset (step 20, 0.005 s), the force component differs by 0.001938 N and moment component by 3.245e-7 Nm, both already beyond tolerance. Session clearance first differs at step 28,100 (7.025 s) by 1.132e-5 m. Common-step contact-pair values remain identical; the WSL run has 60 extra terminal native rows.

A later discrete event compounds the existing trajectory difference: at step 50,160 (12.54 s), Mac enters HOLD and labels the schedule `planning_wait_previous_reference`, while WSL remains OUTBOUND with `outbound_dq_00` until 12.55 s. Mac enters RETURN at 13.055 s and completes at 15.575 s; WSL enters RETURN at 13.065 s and completes at 15.590 s. The registered scorer dwell is 0.600 s Mac versus 0.610 s WSL (absolute difference 0.010 s). The source/receipt version sequences first differ at the request made at 12.54 versus 12.55 s; scientific validity remains PASS on each host. Scorer-v2 physical condition booleans stay PASS, but final q/dq differs.

The other large low-ROM summary differences are peak force 108.719429708 versus 108.578781934 N (0.140647774 N), peak moment 14.435377460 versus 14.444792435 Nm (0.009414975 Nm), and minimum session clearance 0.017871243177 versus 0.017936547842 m (0.000065304665 m), Mac then WSL. They arise in trajectories that started on different robot joint branches; this evidence does not attribute each extremum to the later HOLD threshold alone. All exceed the original tolerance. The original WSL and Mac raw evidence is retained.

## Decision

Y9000P WSL cannot be promoted under the current cross-host equivalence gate. The low-ROM case has a host-dependent initialization branch, and two high-ROM cases exceed the fixed numerical tolerance even though their discrete scientific paths agree. These findings do not prove the WSL host is unsuitable for an independently defined single-host campaign, but such a promotion is **not established by this four-case evidence**. Do not start the 3-rep or 30-repeat baseline from this result.

The minimal production repair target for a separately authorized follow-up is stable initial CR12 IK branch selection in `solve_cr12_stage5_ik` / reset: handle near-tied conditioning scores with a deterministic canonical branch rule and verify identical initial q and torque on both hosts. That repair would not by itself resolve the high-ROM tolerance breaches; assess those separately under the original frozen criterion. This task made no production change, tolerance change, case rerun, RL run or push. Historical realtime and hardware assurance gates remain unchanged.

Detailed per-field first exact and first out-of-tolerance points, absolute/relative errors, row counts, native/trace classifications, scorer metrics and event differences are in `CROSS_HOST_FIRST_DIVERGENCE_DATA.json`; the per-case headline points are in `CROSS_HOST_FIRST_DIVERGENCE.csv`.
