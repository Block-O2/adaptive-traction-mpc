# Learning compatibility

A clean scientific integration is feasible after scheduler acceptance, not yet implemented:

snapshot -> legal candidate generation -> immutable value-model ranking -> unchanged validation/selection -> controller -> committed command receipts -> native transitions.

Ranker receives only request snapshot and admissible candidate/model data. It never emits torque, sees future observations or evaluation truth, or bypasses safety screens. Freeze simulation during inference; record actual inference host time separately for hardware translation. A candidate result is tied to request, phase, Human-model and value-model versions. Value model is immutable within a repetition; Human adaptation has a separately versioned deterministic schedule. Record both request and execution model identities.

Executed transitions start at actual receipt and end at actual physical boundary, with applied candidate/version, control intervals, costs and termination. Predicted, selected-but-rejected and expired plans are not executed transitions. Frozen host waiting has zero physical duration/cost/dwell. Physical fallback intervals remain real executed data with explicit labels; failed/incomplete/contact episodes stay retained and cannot silently enter successful learning-cost data.

Missing/invalid value responses use a preregistered deterministic no-value rule; scientific real wall lateness never chooses that rule. Algorithmic budgets are iteration/event based. Realtime value inference remains deadline-bound, droppable and unable to block active execution. Thus historical asynchronous learning-baseline wording remains appropriate to realtime; scientific mode deliberately changes computation scheduling only.

No learner, dataset, RL training or 30-repeat was implemented/run. Eligibility requires all ACCEPTANCE_TEST_PLAN gates and a separately frozen learning protocol.
