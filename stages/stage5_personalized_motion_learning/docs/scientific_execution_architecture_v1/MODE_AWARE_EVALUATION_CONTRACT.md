## Scoring rule

The existing `summarize_phase_b.score` implementation and its raw output remain unchanged. It is invoked with the registered case and Stage-B scoring contract. Its terminal-state, continuous dwell, phase, force, moment, clearance, contact, ROM, speed, acceleration, torque, timeout and case-hash conditions remain the common physical/task/safety score. `physical_task_result` is PASS exactly when the scorer returns a complete result with every existing condition **except `plan_age`** true, plus no non-finite native/trace state or runtime crash. No threshold is changed. The raw scorer `pass`, `conditions`, and `maximum_plan_activation_age_ms` are retained in the new result for provenance. In particular, a delayed scientific run may have raw scorer-v2 FAIL solely on `plan_age` while the common physical subset passes. Any other scorer-v2 failure fails both modes.

`execution_mode` must be explicit and identical in launch, summary and runtime artifacts; absent, unknown or inconsistent mode fails evaluation. The launcher default remains realtime for historical CLI compatibility, but the evaluation layer never guesses a mode.

For `REALTIME_CHARACTERIZATION`, `realtime_execution_validity` requires the original scorer-v2 `plan_age` condition (strictly <100 ms), no stale activation, control miss, command gap, or host-lateness Safe Fallback. The unchanged runtime lifecycle's >=100 ms stale rejection remains authoritative. Overall PASS requires both the common physical score and realtime execution validity. Scientific validity is N/A.

For `SCIENTIFIC_SIMULATION`, `scientific_validity` requires complete and internally consistent request source, receipt and activation provenance: same episode epoch at receipt; source equals receipt version vector; activation is in the same epoch and has valid current state/phase/model/reference identity for the activation transaction; original source simulation age and physical horizon remain enforced. Any unknown/missing version or request error fails. Physics steps and task/reference/model versions must remain constant during the frozen computation. Overall PASS requires the common physical score and scientific validity. Realtime validity is N/A; a counterfactual stale flag may be shown, but cannot change scientific result. Host compute time, activation latency and full plan/source wall age are always reported honestly.

The fixed safety/task conditions apply in both modes. Smoothness/C2 and reference correctness use existing certificates/diagnostics where applicable; missing required evidence fails. No evaluation truth may feed planner/controller action. This evaluation does not establish robustness, realtime readiness or hardware safety. Historical `RSS_RUNTIME_QUALIFICATION_NOT_MET` and `RUNTIME_ASSURANCE_REQUIRED_BEFORE_HARDWARE_EXPERIMENTS` remain.

## Fresh validation preregistration

First run deterministic tests for scorer history, exact 100 ms realtime rejection, scientific long-wall-age acceptance with fixed version, short-wall-age wrong-version rejection, explicit mode, shared physical conditions, truth firewall and legacy wrapper. Then perform four **new** scientific runs of the same registered 120/120 synchronous case with injected host delays 0, 100, 200, 500 ms, separate output directories, unchanged source/config/seed. All must be COMPLETE, common physical PASS, scientific PASS, and exactly identical across all 48 trace arrays, every native time/qpos/qvel/torque/contact state, waypoint labels and phase-transition simulation times on this host. Identical NaN masks are permitted only where already present; no numeric tolerance is allowed for finite values. Wall ages must grow and remain reported. Old V1 runs are comparison background only, never a new PASS.

After those gates, run one small realtime nonregression and only then 4–8 fixed representative scientific cases: low-ROM ordinary, high-ROM, 120/120 synchronous and 120/120 variable-start. Every selected run must meet common physical, provenance, no-future-leakage and scientific gates; no failed run is excluded. The existing registered case inputs and scoring limits are not changed to obtain PASS. A gate failure stops dependent runs and is recorded as a negative result. No 30-repeat, value learning, RL, hardware actuation or WSL run is part of this contract.

Quota and time gates follow the user's current prompt: at >=36% no added diagnostics/cases; at >=36.5% do not start representatives if not started; at >=37% stop project model continuation. No representatives start after 2.5 hours; close out by 3 hours.
