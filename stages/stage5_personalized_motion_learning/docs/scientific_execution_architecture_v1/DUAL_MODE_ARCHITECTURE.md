# Dual-mode architecture

Decision: SCIENTIFIC_MODE_MODERATE_REFACTOR. A finite scheduler/lifecycle refactor is feasible without rewriting controller mathematics. This is an architectural judgment, conditional on the tests below; it is not validation of an implemented mode. The previous runner-only NOT_JUSTIFIED assessment remains valid for its narrower scope.

| Option | Change scope | Determinism / leakage | RSS / fallback compatibility | Maintenance / later RL | Realtime isolation |
|---|---|---|---|---|---|
| A Fully blocking | New inline executor plus extraction of shared async-path transitions | Strong; by-value snapshot still needed | Risk of accidentally selecting existing legacy synchronous branch; must port shared readiness/escape preparation | Simple runtime, more path convergence work | Separate adapter possible |
| B Async worker, frozen epoch | Reuse serialized worker; barrier before ANY further scientific mutation; explicit receipt/staged activation policies | Strong if callbacks are telemetry-only and activation uses a fresh transaction | Preserves execute_task_snapshot and prepare_decision; keeps geometric bridge/stop | Moderate integration changes; natural versioned value worker | Existing wall executor retained |
| C Event queue | Broad new queue, priorities, serialization and event ownership | Strong if event order and all ties fixed; substantial hidden-state audit | Must express reference/fallback/terminal events anew | Flexible for future RL, excessive current scope | Larger regression surface |

Recommend only B. Freeze immediately on critical submission, not merely when a later endpoint needs the result. A worker that completes in 20 ms, 200 ms or 2 s is received at the same simulation boundary. No spinning control loop or speculative stepping while waiting. Thread/process callbacks cannot advance logical state; main owner performs ordered consumption. Use the existing process isolation; executor injection permits deterministic test doubles.

ClockProvider keeps physical and host clocks distinct. ExecutionPolicy owns freshness/terminal validity and fault classification. Scheduler owns barrier, fixed steps, acquisitions, receipt commit, finalization and result visibility. Shared controller/planner/estimator/reference math receives ordinary numeric inputs, never mode flags. Construct the mode once at runner composition; avoid scattered scientific_mode conditionals.

Existing seams: PlanLifecycle already accepts a clock, snapshot_task_call serializes by value, _execute_interval centralizes command writing, WallPhysicsSession is single-owner, and reference history already accepts a physical clock. Obstacles: runtime.py directly branches on wall_session/online_timing, closes over mutable belief/phase during validation, emits monotonic reads in splice/terminal paths, and ties Safe Fallback enablement to async timing. Extract orchestration only; a fake monotonic clock alone cannot solve this.

RSS in both modes keeps C2 stitching, polynomial suffix/bridge geometry, receipt-based acceleration constraints and independent safety screens. For first scientific implementation preserve the existing 40 ms geometric continuation and registered fork/splice rules, even though host-lateness mitigation is unnecessary. Earliest allowed splice follows physical progress and existing geometric admission, not future.done wall arrival. Do not delete or shorten bridges to improve task scores.

REALTIME Safe Fallback retains wall-late/expired primary -> committed certified stop -> nonpreemptible braking -> separate hold -> fresh request/validation. SCIENTIFIC host slowness produces no fallback; deterministic algorithmic failures retain the same certified escape and physical fork/stop transitions where coverage exists. Rejection outside coverage preserves existing abort outcome; no new commissioning brake guarantee is implied. Stop velocity/reference and measured state checks remain distinct.

COMMISSIONING can use state_k -> same supervised torque_k -> apply -> exactly 5 ms simulation -> state_k+1. A 150 ms host compute changes completion time only. This preserves the discrete control law and MuJoCo plant with ideal timely sample-and-hold execution. It deliberately differs from wall-causal missed-deadline physics; it does not reproduce stalls or demonstrate CR12 200 Hz hard realtime. Initialization, measurement noise draw order and fit/replay must also be frozen/deterministic.
