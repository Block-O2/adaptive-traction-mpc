# Truth firewall audit — mode-aware v1

Date: 2026-09-29. Scope: the registered High-ROM scientific path and its planner worker. Outcome: **PASS for the inspected path and bounded injection tests**. This is a software dataflow result, not a formal proof of every possible Python object graph or future hardware integration.

`runtime.py` builds the task planner from the scheduler, current estimated Human model, structural/causal clearance object and registered options. The task request passes `belief`, `current_deployable_state`, current reference, phase and task clocks to `snapshot_task_call`; it does not pass `plant`, `truth`, evaluation-only state or `runtime`. `online_planning.py` pickles the planner and argument graph into local bytes before worker submission, then deserializes those bytes inside `execute_task_snapshot`. The worker receives no live MuJoCo pointer. A test mutates the original input array after snapshot and confirms the worker sees the original values. The planner's decision method uses the passed belief/state/reference; simulation truth appears only in the owner thread's physical evaluation/logging path.

`ScientificPlanLifecycle.submit` joins the worker before returning to the owner thread. The `ScientificPhysicsSession` only advances native physics in explicit `next_control_tick`, and its `catch_up` records zero native steps. Source and receipt `SimulationVersion` must match exactly; epoch, state, physics step/time, phase, Human model sequence and reference receipt count are recorded. Injected physics-step, episode, state, phase, model and reference changes during the wait are rejected in deterministic tests. The result record preserves source, receipt and activation vectors and actual host timestamps. Activation may occur after controlled bridge steps, so activation's physics/reference tokens may legitimately differ from the planner source; fresh activation feasibility/C2 checks and simulated source-age guards apply at that boundary. The evaluation layer rejects absent version fields, source/receipt mismatch, epoch or phase mismatch, reversed physical step, stale simulated source and missing activation certificates.

The recorded 0/100/200/500 ms V1 native trajectories were exactly equal; this corroborates frozen physical execution but is not reused as V2 acceptance. No future-state leak was found in the inspected worker input flow. Logging and scorer code operate after decisions on separate output artifacts; no path from post-run scoring into planner action was identified. `truth_consumed` is required false in every activation certificate.

Limit: `state_version = native steps + sample count`, `reference_version = applied-command count`, and `phase_version` is derived from phase records/task counter. These are operational tokens rather than a proof that every mutable object has its own monotone counter. The single-owner frozen computation plus by-value payload closes the concurrent future-read path exercised here. Broader object-graph mutation coverage would require a separately scoped audit; this result must not be promoted into a universal truth-firewall guarantee.
